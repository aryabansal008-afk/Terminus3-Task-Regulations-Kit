# Checklist: Task Design & Novelty
(REGULATIONS.md §1)

- [ ] Goal is clear, specific, unambiguous
- [ ] Every requirement is inferable from provided materials
- [ ] Grounded in a realistic software engineering / technical domain
- [ ] Requires genuine debugging/implementation/investigation, not shallow reasoning
- [ ] Requires multi-step reasoning, intermediate state, branching, recovery, or reacting to previous results
- [ ] Cannot be solved by a single command or straight-line script
- [ ] Difficulty comes from reasoning, not prompt ambiguity
- [ ] No unnecessary complexity
- [ ] Fully specified, deterministic, self-contained, objectively verifiable (Testable)
- [ ] Not a reskin / near-duplicate of Terminal-Bench 2.1, Terminal-Bench 3.0, or earlier Terminus tasks — checked on BOTH computation and problem setup
- [ ] For narrow technical-domain tasks: novelty compared at the level of the specific mechanism exercised, not just category/subcategory label
- [ ] Exactly one category + one subcategory from official taxonomy
- [ ] No canary strings anywhere in the repo
- [ ] See also 13_standalone_internet_language.md for Standalone/Language checks
